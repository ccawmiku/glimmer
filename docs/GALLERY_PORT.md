# 潜在空间画廊移植评估与验证

## 来源与模式

读取的是较新的 `ccawmiku/latent-art-wallpaper` 默认 `dev` 分支，参照提交为 `db934a9d60397db8c0a3bbefb1f007bb3a6616e0`。其随机画布模式（原称随机宇宙）每次重新创建解码器和隐向量，与固定网络中的成长、逐维演化不同。

移植只提供这一模式，固定使用默认经典色板、双轴条纹、自动 Z 顺序、ReLU 第二隐藏层和自动颜色数量；其他模式的控制和状态不进入固件。控制面板中唯一的画廊专属设置是刷新间隔。

## 神经网络移植难度

原随机网络为 `192→96→64→64`，共有 28672 个权重、224 个偏置。单是 Float32 权重就需要 114688 字节（112 KiB），加偏置约 112.9 KiB；设备既无 PSRAM，也只有约 30 KB 运行堆，直接保留原矩阵不可行。

原项目使用随机初始化的网络，没有需要部署的训练模型。固件采用可复现的 32 位随机种子，按原构造器的顺序重建权重并立即计算每个神经元；不保存完整矩阵。保持原网络尺寸、初始化分布、第一层 tanh、第二层 ReLU、线性输出、物理参数映射、经典色板能量选择、条纹采样与遮盖顺序。因此不需要使用另一个程序化方法替代神经网络。

权重生成涉及约 2.9 万次乘加和软件浮点计算；真实 ESP8266 的生成耗时通过 `/api/state` 的 `gallery_decode_us` 暴露，最终速度需设备实测。计算期间定期 `yield()` 避免看门狗超时。最短刷新间隔设为 1 秒，不做连续动画。

内存分配：

| 项目 | 占用 |
|---|---:|
| 静态画面描述（最坏 480 条条纹及 64 维输出） | 6024 字节 |
| 一行 RGB565 缓冲 | 480 字节 |
| 隐向量、两隐藏层和输出偏置的临时数组 | 1664 字节 |
| 全屏 16 位缓冲 | 不分配，原本需 115200 字节 |
| 常驻权重矩阵 | 不分配 |

画面在 CPU 上逐行完成颜色叠加，然后每行只上传一次。`tick()` 不清屏，不把中间条纹层直接暴露到 LCD；画廊也不叠加轮播进度条。第一次显示与重新进入时按照间隔生成；隐藏期间不生成。

## 已执行验证

- 固件使用 ESP8266 真正的 Xtensa 工具链完成编译和链接。
- LittleFS 镜像构建成功，包含六个实际使用的字体及中文 HTML、CSS、JS；无外部网页运行库。
- `tests/verify_gallery.py` 使用与设备共用的 C++ 引擎，对比保留的上游原始 JS 模块。64 个种子生成 64 张不同画面；64 维神经输出最大绝对误差为约 `3.61e-7`；全部可见条纹的位置、宽度、RGB565 颜色与遮盖顺序一致，故对应像素一致。
- 上游在极少数情况下会在 `pos=240` 产生完全位于画布外的条纹，设备端跳过，参照测试也过滤这些不可见条纹。
- Chromium 验证中文状态页、来自固件描述的预览、固定显示画廊、刷新间隔请求、UTC 零偏移、凭据掩码保留、网络/额度独立保存、中文刷写入口和手机布局；浏览器脚本无异常。API 使用模拟响应，未冒充实机连接。
- 按 Arduino `elf2bin` 的方法还原 CRC 字段后，校验 eboot 与应用段的原始校验和及整固件 CRC，均通过。
- 下载包包含两个分区镜像与串口合并镜像，镜像地址和长度按当前链接脚本核对，校验值见包内 `SHA256SUMS`。

本任务环境没有连接物理 SmallTV，也没有用户的额度凭据，因此未执行物理刷机、LCD 色彩/帧耗时实测或在线额度认证。网页截图来自浏览器验证，示例画廊图来自实际移植引擎，均不冒充设备拍照。

## 本地复现

```bash
python tests/verify_gallery.py
npm ci
npx playwright install chromium
npm run test:web
python -m platformio run -e nodemcuv2
python -m platformio run -e nodemcuv2 -t buildfs
python tools/package.py
```

许可证见仓库 `THIRD_PARTY.md`。参照模块仅用于开发验证，不进入 LittleFS 镜像。
